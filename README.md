# Monorepo Single Worker — React + Hono + Cloudflare Vite Plugin

A full-stack application using React, Vite, Hono, and Cloudflare Workers, organized as a monorepo and deployed as a single Cloudflare Worker.

The main feature of this setup is the Cloudflare Vite plugin, which integrates the React frontend and Hono Worker during development and deployment.

## Stack

* **React** — frontend
* **Vite** — frontend development and build tool
* **Hono** — backend/API framework
* **Cloudflare Workers** — application runtime
* **Cloudflare Vite Plugin** — integrates Vite with the Cloudflare Worker
* **Wrangler** — Cloudflare CLI and deployment tool

## Project Structure

```text
project/
├── web/
│   ├── src/
│   ├── public/
│   ├── package.json
│   ├── vite.config.ts
│   └── dist/              # Generated by the build
│
└── api/
    ├── src/
    │   └── index.ts
    ├── package.json
    └── wrangler.jsonc
```

The `web` directory contains the React/Vite frontend, while `api` contains the Hono Worker.

# Cloudflare Vite Plugin

The Cloudflare Vite plugin is the key part of this architecture.

Without the plugin, Vite and Wrangler are generally treated as separate development servers. For example:

```text
Vite
localhost:5173
    │
    │
    │ HTTP request
    ▼
Hono / Wrangler
localhost:8787
```

This means the frontend and backend have different origins.

With the Cloudflare Vite plugin, the Worker is integrated into the Vite development environment:

```text
              Vite
        localhost:5173
              │
       ┌──────┴──────┐
       │             │
    React           Hono
   frontend          API
       │             │
       └──────┬──────┘
              │
         Same origin
```

This is particularly useful because the frontend can communicate with the Hono API using **relative URLs**.

---

# Relative API URLs

Instead of configuring a separate backend URL:

```js
const API_URL = "http://localhost:8787";

fetch(`${API_URL}/api/events`);
```

the frontend can simply use:

```js
fetch("/api/events");
```

The browser automatically uses the origin that served the frontend.

### Development

```text
fetch("/api/events")
        ↓
http://localhost:5173/api/events
```

### Production

```text
fetch("/api/events")
        ↓
https://your-app.com/api/events
```

This means the frontend does not need to know the backend's hostname or port.

You don't need to switch between:

```text
localhost:8787
```

during development and:

```text
https://your-app.com
```

in production.

The same code works in both environments:

```js
fetch("/api/events");
```

# CORS Benefit

One of the biggest development benefits of the Cloudflare Vite plugin is avoiding the cross-origin setup that would otherwise be necessary when Vite and Wrangler run on different ports.

For example, without integration:

```text
React
http://localhost:5173
        │
        │ cross-origin request
        ▼
Hono
http://localhost:8787
```

Because the ports are different, these are different origins.

That can require CORS configuration on the backend:

```text
http://localhost:5173
        │
        │
        ▼
   CORS handling
        │
        ▼
http://localhost:8787
```

With the Cloudflare Vite plugin, the frontend and Worker operate through the same development origin:

```text
http://localhost:5173
        │
        ├── React frontend
        │
        └── /api/*
              │
              ▼
          Hono Worker
```

Therefore, a request such as:

```js
fetch("/api/events");
```

is same-origin.

The browser sees:

```text
Frontend: http://localhost:5173
API:      http://localhost:5173/api/events
```

rather than:

```text
Frontend: http://localhost:5173
API:      http://localhost:8787/api/events
```

This removes the need to configure CORS simply because the frontend and backend are running on different development ports.

> **Important:** The plugin doesn't fundamentally eliminate CORS from the web platform. It avoids the cross-origin situation in this development architecture by putting the frontend and Worker behind the same origin.

# Development

With the Cloudflare Vite plugin, you do **not** need to separately run:

```bash
wrangler dev
```

for the Hono backend.

Instead, from the `web` directory:

```bash
npm run dev
```

Vite starts the development environment and integrates the Cloudflare Worker.

This gives the frontend and backend a unified development experience.

Your React code can therefore make API requests directly:

```js
fetch("/api/events");
```

rather than having to configure something like:

```js
const API_URL = "http://localhost:8787";

fetch(`${API_URL}/api/events`);
```

# Production Build

The application is built from the `web` directory.

```bash
cd web
npm run build
```

Vite builds the React frontend and, through the Cloudflare Vite plugin, integrates the Worker configuration from:

```text
../api/wrangler.jsonc
```

The generated output is placed in:

```text
web/dist/
```

The build output contains the Worker and frontend assets needed for deployment.

Conceptually:

```text
web/dist/
├── wrangler.json
├── _worker.js
└── assets/
    ├── ...
    └── ...
```

The exact generated files can vary with the plugin/Vite version, but the important point is that the build produces a deployable Cloudflare Worker configuration and the frontend assets.

---

# Deployment

After building:

```bash
cd web
npm run build
```

deploy the generated output:

```bash
npx wrangler deploy
```

The deployment flow is therefore:

```text
             npm run build
                   │
                   ▼
             Vite build
                   │
          ┌────────┴────────┐
          │                 │
      React build       Worker build
          │                 │
          └────────┬────────┘
                   ▼
                web/dist
                   │
                   │
            wrangler deploy
                   │
                   ▼
          Cloudflare Workers
```

Once deployed, both the React frontend and Hono API are available through the same production origin.

For example:

```text
https://your-app.com/
```

serves the React application, while:

```text
https://your-app.com/api/events
```

is handled by the Hono API.

# Development vs Production

The important part of this architecture is that the frontend code does not need to change between development and production.

### React

```js
fetch("/api/events");
```

### Development

```text
http://localhost:5173/api/events
```

### Production

```text
https://your-app.com/api/events
```

The browser resolves the relative URL against the current origin.

This is one of the main advantages of serving the frontend and API through the same Worker/origin.

# Why Use the Cloudflare Vite Plugin?

The biggest benefit for this architecture is **development integration**.

Without the plugin, you can run Vite and Wrangler separately, but you then have to deal with two development origins:

```text
localhost:5173  → React
localhost:8787  → Hono
```

That makes API URLs and CORS more complicated.

With the Cloudflare Vite plugin:

```text
localhost:5173
      │
      ├── React
      │
      └── Hono /api/*
```

This allows the application to use:

```js
fetch("/api/events");
```

throughout development and production.

The result is a simpler full-stack development model:

```text
              React
                │
                │ /api/*
                ▼
          Hono Worker
                │
                ▼
          Cloudflare
```

**One application, one origin, one API URL pattern.**
